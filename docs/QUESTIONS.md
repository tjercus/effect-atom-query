# Decisions and open questions

## Decided

| ID  | Question                                  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | How are queries defined?                  | **Atom-first with a thin compat layer.** Use `Query.make({ key, run })` at module level and call `useQuery(todoQuery(id))`. `queryOptions`, `infiniteQueryOptions` and `mutationOptions` are thin aliases to ease porting. Inline `useQuery({ queryKey, queryFn })` is not supported.                                                                                                                                                      |
| D2  | What does `useQuery` return?              | **TanStack-style fields and flags plus `result: AsyncResult`, but never `undefined`.** `data`, `error`, `failureReason`, timestamps and getters (`getQueryData`) are `Option`s. The result is a discriminated union on `status`, so `isSuccess` narrows `data` to `Option.Some<A>`. Suspense and `initialData` variants expose `data: A` directly.                                                                                         |
| D3  | What is in v1 besides the core?           | **Suspense and error boundaries, infinite queries, and persistence with offline support.** SSR and hydration come after v1.                                                                                                                                                                                                                                                                                                                |
| D4  | Does `QueryClient` get an imperative API? | **Effect only.** There is no Promise or sync facade and no `mutateAsync`. `useMutation` exposes `mutate` (fire and forget) and `mutateEffect`.                                                                                                                                                                                                                                                                                             |
| D5  | What is the project called? (2026-11-14)  | **effect-atom-query**, renamed from effect-native-query. Packages: `@effect-atom-query/query`, `@effect-atom-query/react`, `@effect-atom-query/devtools`. "http" was rejected because `run` can be any Effect, not only HTTP.                                                                                                                                                                                                              |
| D6  | Publishing (2026-11-14)                   | **Prepare, don't publish yet.** Package metadata, Changesets, a release script and a CI publish dry run are set up; the owner claims the `@effect-atom-query` npm org and publishes manually. Superseded by D12 (2026-11-15).                                                                                                                                                                                                              |
| D7  | Are cancellations visible? (2026-11-14)   | **Never.** As in TanStack, a cancelled or superseded fetch returns the query to its previous state (or `idle`); interrupt-only causes never reach `error`, error boundaries or `onError`.                                                                                                                                                                                                                                                  |
| D8  | Key representation (2026-11-14)           | **Plain tuples**, `readonly [string, ...unknown[]]`, compared structurally with `Equal` and prefix-matched by filters. No Schema required for keys; persisted queries only need JSON-compatible keys (`QueryKey.toJsonKey`). No key factory.                                                                                                                                                                                               |
| D9  | Devtools packaging (2026-11-14)           | **Separate optional package**, `@effect-atom-query/devtools`, stripped in production. No browser-extension integration for now.                                                                                                                                                                                                                                                                                                            |
| D10 | Effect language service (2026-11-14)      | **Keep it configured and track it.** TypeScript 7's native compiler has no plugin API, so the `@effect/language-service` tsconfig plugin is inert for now; Effect diagnostics return once TS 7 supports plugins or the language service integrates with tsgo.                                                                                                                                                                              |
| D11 | Promises at the edge (2026-11-15)         | **Purely Effect inside, one helper at the edge.** D4 stands: the core, the `QueryClient` API and the hooks are Effect-only, and the library uses no Promises for its own logic (Suspense's thrown Promise is React's contract). `useRunEffect()` in the React package runs an Effect in the client's context and returns a Promise, for form libraries, route loaders and callbacks. No `mutateAsync` / `mutateExit`. See PLAN-1.3.md WP4. |
| D12 | Publishing from CI (2026-11-15)           | **Replaces D6.** Releases are published only by the Release workflow, with npm trusted publishing (OIDC, no stored token) and provenance. Prereleases go to `next`, stable versions to `latest`; `latest` gets at most one release per 7 days except security fixes, enforced by `scripts/release-guard.ts`. Process and support policy: RELEASING.md.                                                                                     |
| —   | Persistence storage targets               | **Any `KeyValueStore`** (resolved in phase 6): localStorage, IndexedDB, memory, file system, SQL, AsyncStorage via a custom store.                                                                                                                                                                                                                                                                                                         |
